# Design Review Checklist

Use this checklist before developers start implementing a feature to ensure alignment, usability, and feasibility.

## 📝 Preconditions
- [ ] Problem statement is clearly defined
- [ ] Success criteria or acceptance criteria are documented
- [ ] Relevant stakeholders have been identified (PM, UX, Dev, Security)

## 🎨 UX & Workflow
- [ ] User flows are documented and reviewed
- [ ] Wireframes/mockups are linked and accessible
- [ ] Accessibility considerations are addressed (contrast, keyboard nav, screen reader)
- [ ] Error states and edge cases are defined
- [ ] Mobile/responsive behavior is considered (if applicable)

## ⚙️ Technical Feasibility
- [ ] Design is reviewed with development for feasibility
- [ ] Required APIs, services, or integrations are identified
- [ ] Constraints and assumptions are documented
- [ ] Performance considerations addressed

## 🔐 Security & Compliance
- [ ] User data handling reviewed (PII, storage, validation)
- [ ] Authentication & authorization flows considered
- [ ] Threat modeling (basic) completed if applicable

## 📄 Documentation
- [ ] Design specs updated and stored in approved location
- [ ] Linked in the corresponding issue/ticket
- [ ] Stakeholders approved the design

## ✔️ Final Approval
- [ ] PM approval
- [ ] UX approval
- [ ] Engineering lead approval
